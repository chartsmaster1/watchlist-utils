# Agent Instructions

## Project purpose

`watchlist-utils` is a Python data-preparation project. Scripts under `public/src/` download or read financial data and write frontend-ready JSON and CSV files under `public/data/`. The static frontend is in `public/` and consumes the generated files directly.

Keep changes focused on data correctness, repeatable refreshes, and preserving the existing output schemas. Do not commit generated data or configuration changes unless the task explicitly asks for refreshed artifacts.

## Repository layout

- `public/src/main.py`: orchestrates all data-preparation jobs.
- `public/src/prep_*.py`: individual source adapters and output writers.
- `public/src/notify_run.py`: emails the scheduled-run summary (success or failure); SMTP settings come from the gitignored root `config.json` or environment variables, and the same text is written to `logs/last-run-summary.txt`.
- `public/src/common/wiki.py`: schema-based Wikipedia table selection.
- `public/src/common/marketcap_live.py`: CompaniesMarketCap HTML scraper.
- `public/src/common/tickers.py`: ticker aliases used when joining index data to market caps.
- `public/data/*.json`: frontend data consumed by `public/index.html`.
- `public/data/*.csv`: companion/export files.
- `config.json`: local CoinMarketCap credential configuration; never print, commit, or include its contents in responses.

## Environment and commands

Run commands from the repository root unless a command explicitly says otherwise:

```bash
python3 -m pip install -r requirements.txt
python3 -m py_compile public/src/*.py public/src/common/*.py
python3 public/src/test.py
```

Individual refresh commands:

```bash
python3 public/src/prep_companies_market_cap.py
python3 public/src/prep_etfs_market_cap.py
python3 public/src/prep_coins_market_cap.py
python3 public/src/prep_arkk.py
python3 public/src/prep_dow.py
python3 public/src/prep_nasdaq.py
python3 public/src/prep_sandp.py
python3 public/src/prep_sandp_sectors.py
python3 public/src/prep_russell_1000.py
```

The source-backed index jobs depend on `public/data/stocks.json`, so refresh CompaniesMarketCap before Dow, NASDAQ, S&P 500, or Russell 1000 when current market-cap ordering is required. Run `prep_sandp_sectors.py` after `prep_sandp.py` because it reads `s&p500.json`.

`main.py` is the full orchestrator and should be run only when a complete refresh is intended:

```bash
python3 public/src/main.py
```

It runs the company market-cap job, index jobs, sectors, ETFs, coins, Russell, and ARKK. It performs network requests and overwrites generated files; do not use it as an import-only module.

## Data sources and outputs

- Companies and global stock market caps: `https://companiesmarketcap.com/`, scraped by `common/marketcap_live.py`; writes `stocks.json` and `stocks.csv` (the latter may not be generated by the current preparer).
- S&P 500, NASDAQ-100, Dow, and Russell 1000 constituents: dedicated Wikipedia list pages selected by required column schema in `common/wiki.py`.
- ETF rankings and market caps: `https://8marketcap.com/etfs/`; writes `etfs_market_cap.json` and `etfs_market_cap.csv`.
- Cryptocurrency listings: CoinMarketCap API; requires a local root `config.json` containing `CMC_API_KEY` and writes `coins.json` and `coins.csv`.
- ARKK holdings: ARK Invest CSV at `https://assets.ark-funds.com/fund-documents/funds-etf-csv/ARK_INNOVATION_ETF_ARKK_HOLDINGS.csv`; `prep_arkk.py` downloads and validates it, then writes `arkk_holdings.csv`, `arkk.json`, and `arkk.csv`.
- S&P sector groupings: derived from `s&p500.json`; writes `spysectors.json` and `spysectors.csv`.

## Safe editing rules

- Use paths based on `Path(__file__).resolve()` for data files. Do not reintroduce paths such as `../data/...` that depend on the current working directory.
- Network requests must use a timeout, a descriptive User-Agent where practical, and `raise_for_status()` before parsing.
- Validate response shape and required columns before overwriting an existing output.
- Keep source tickers in output. Use a separate normalized join key for market-cap matching so aliases such as `GOOGL` and `GOOG` do not create duplicate output tickers.
- Do not silently drop constituents to make a join pass. Preserve the constituent and emit a clear missing-market-cap warning when the market-cap source has no match.
- Do not use Python `assert` for production data validation; assertions can be disabled with optimization flags. Raise `ValueError` or report a deliberate, actionable validation error instead.
- Avoid logging or printing API keys, response secrets, or full credential files.
- Be careful with `error.log`: several legacy modules configure logging with `filemode='w'`, so running a script can replace existing log contents.
- Generated JSON/CSV updates are expected after a refresh, but unrelated generated changes must not be reverted.

## Known data limitations

- `stocks.json` currently contains only the first 4,000 CompaniesMarketCap rows. Some Russell 1000 constituents therefore have no market cap. This is a coverage limitation, not necessarily a ticker-parser failure.
- Some index symbols are stale, have changed, or use share-class variants. Check `public/src/common/tickers.py` before adding a one-off exclusion or alias.
- ARKK has cash, warrants, and other rows with blank tickers; the preparer intentionally excludes rows without tickers from the derived holdings output.
- CoinMarketCap returns up to 1,000 records with the current request parameters. API rank order is not guaranteed to be identical to descending market-cap order; sort explicitly if a consumer requires market-cap ordering.
- `arkk.json` is ordered by holding weight, not market cap. `spysectors.json` is grouped by sector, not ranked.
- External Wikipedia and market-data HTML layouts can change. Prefer schema/required-column selection and fail with a useful message rather than relying on blind table indexes.

## Validation after changes

After editing a preparer:

1. Compile the touched modules:
   `python3 -m py_compile public/src/*.py public/src/common/*.py`
2. Run the narrowest affected refresh command from the repository root.
3. Verify the output JSON parses, is non-empty, has the expected fields, and has no blank or literal `"nan"` tickers.
4. For ranked files, check ordering and whether missing values are intentionally at the end.
5. Run `python3 public/src/test.py` when shared code, orchestration, or multiple preparers changed.
6. Run `git diff --check` and inspect `git status --short` before reporting completion.
7. When touching scheduled-run notifications, run `python3 public/src/notify_run.py --dry-run --exit-code 0` (and `--exit-code 1`) to confirm the email renders without sending.

For read-only comparisons, use:

```bash
python3 public/src/compare_wiki.py
python3 public/src/compare_marketcap.py --pages 3 --delay 0.1
```

The market-cap comparison is intentionally sampled by default. Increasing `--pages` performs more live requests and may still show missing index symbols because of ticker aliases and source coverage.

## Frontend contract

Before changing output keys or filenames, check `public/index.html`. Existing datasets are referenced by filenames such as `stocks.json`, `etfs_market_cap.json`, `coins.json`, `arkk.json`, and `spysectors.json`. Preserve those names and their public field names unless a coordinated frontend change is requested.
